# CreditWise

**A Prolog Based Expert System for Personal Loan Eligibility Assessment and Risk Classification**

## 1. What the system does

CreditWise assesses a personal loan application and produces three outputs:

1. a **decision**: approve, approve with conditions, or reject
2. a **risk grade**: low, medium or high (not applicable when rejected)
3. an **explanation** showing exactly which rules fired and where each rule came from

It replicates the branch level assessment carried out by a loan officer at National Savings Bank.

## 4. How to run

Open a terminal in the folder containing these files and type:

```
swipl creditwise.pl
```

At the `?-` prompt type:

```
start.
```

Remember the full stop. Prolog will not execute a goal without it.

A menu appears:

```
  1. Assess a new loan application
  2. Explain the last decision (forward chaining trail)
  3. Prove a goal (backward chaining)
  4. Run the built in test cases
  5. Show the knowledge base (facts and rules)
  6. Show the facts currently in working memory
  0. Exit
```

To leave the program choose `0`, then type `halt.` at the Prolog prompt.

### Running the tests without the menu

```
swipl -q -g "run_tests, halt." creditwise.pl
```

## 7. The two inference mechanisms

Rules are declared once, as data, in the form

```prolog
rule(Id, Stratum, Conclusion, [Condition, ...], Description).
```

This lets **one** rule base be executed by **two** different engines, which is what allows the assignment requirement for both mechanisms to be met without duplicating any knowledge.

**Forward chaining** (`forward_chain/0`) is data driven. It starts from the facts in working memory and fires every rule whose conditions hold, asserting each conclusion, until no further conclusion can be added. This produces the recommendation and the reasoning trail.

Rules are grouped into four strata so that negation as failure is safe. A rule containing `absent(G)` is never evaluated until every rule that could derive `G` has already run.

| Stratum | Derives |
|---|---|
| 1 | individual eligibility tests |
| 2 | overall eligibility, rejection triggers, individual risk factors |
| 3 | the overall risk grade (worst factor wins) |
| 4 | the decision, its conditions and standing requirements |

**Backward chaining** (`prove/2`) is goal driven. It is a meta interpreter: given a goal such as `decision(approve)` it finds rules that conclude it, then recursively proves each condition, until it reaches facts in working memory. It returns a proof tree which the explanation facility prints. It works directly from working memory and does not need forward chaining to have been run first.

## 9. Four findings worth noting

**The minimum monthly income is Rs. 30,000.** At Part 1, Q3 the expert took none of the five printed options, marked "other" and entered it, then confirmed it on review. Rule R4 applies it as a hard eligibility gate, and rule R25 makes income below it an immediate rejection.

**NSB applies no minimum years in business.** Part 1 Q5 looks like a one year minimum, but the free text beside it says a loan is granted at the start of a business once the proposal has been evaluated, and the expert confirmed this on review. The one year figure only selects which assessment route applies. A trading business is assessed on its history (R7), a new business on its evaluated proposal (R8), and neither is a barrier to the other. Rules R7 and R8 state this explicitly and `min_business_years_applied` is recorded as `no`.

**NSB is unusually tolerant of past credit problems.** The expert answered "approve" for one late payment, for two or more late payments, for a settled default and for an **unsettled** default, and in Part 5 deliberately did not tick "unsettled default" as an immediate rejection trigger. Two independent answers agreeing means this is a real institutional position rather than a slip. What NSB does reject is a borrower who is *currently* in arrears, or one with a write off or recorded legal action. Rule R22 implements this and cites both answers.

**The debt to income ratio is used for eligibility but not for grading.** The expert wrote "not consider" against both risk grading bands in Part 3 while selecting a firm 60% ceiling in Part 1. The system therefore uses the ratio as a hard eligibility gate only, and grades risk on employment type, length of service and CRIB record.

## 10. Troubleshooting

**`start.` does nothing.** Check the full stop at the end.

**Nothing happens after typing a number.** Press Enter.

**"Unknown procedure: start/0".** Run `swipl creditwise.pl` from inside the folder holding all six files, not from elsewhere.

**Option 2 says no assessment has been run.** Run option 1 or option 4 first, so that working memory contains an applicant.
